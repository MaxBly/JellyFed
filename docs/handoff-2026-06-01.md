## 1. Ce qui a été livré (commits inclus)

### A2 — Durée par source (films + épisodes)

Avant : toutes les versions d'un film affichaient la même durée (celle du peer primaire) — bug visible sur Midsommar VF 2h27 / Director's Cut 2h50 qui affichaient toutes 2h27.

Après : chaque `MediaSourceInfo` exposée au pipeline JF porte sa vraie durée. `ManifestSource.RuntimeTicks` (long?), `BuildSource` calcule via `TimeSpan.FromMinutes(item.RuntimeMinutes).Ticks`, idem dans `BuildEpisodeSources` pour les épisodes. Provider : `RunTimeTicks = source.RuntimeTicks ?? item.RunTimeTicks`.

### A3 — MediaStreams par source complets

Avant : `MediaStreamInfoDto` ne portait que `Type/Codec/Language/Title/IsDefault/IsForced` ; le `Index` était forcé à -1 dans `ToMediaStream` → impossible côté dew d'afficher les pistes audio/sous-titres ou de proposer une sélection fiable, infos fichier vides sur les sources alternatives.

Après : `MediaStreamInfoDto` enrichi de `Index, Channels, BitRate, Width, Height, SampleRate, VideoRange`. Le stream `Video` (auparavant absorbé en codec/width/height du DTO racine) est désormais exposé dans la liste `MediaStreams[]` à part entière. `ExtractStreamInfo` peuple tout depuis les `MediaStream` natifs JF. `ToMediaStream` mappe fidèlement (vrais index, channels audio, bitrate).

### A6 — Métadonnées de source pour tri

Avant : impossible côté dew de trier/étiqueter les sources alternatives (« 4K HDR DV » vs « 1080p SDR »). Le sélecteur `#198` ne pouvait pas badger « 4K » ou « HDR ».

Après : `ManifestSource` + `CatalogItemDto` + `EpisodeDto` portent `BitRate, SizeBytes, VideoRange, Edition`. La détection HDR utilise `MediaStream.VideoRangeType` (HDR10/HDR10+/DV/HLG) puis fallback sur `VideoRange` (SDR/HDR). L'édition est extraite du filename via regex `[edition-XXX]` ou `{edition-XXX}`. `MediaSourceInfo.Bitrate` et `Size` sont propagés au provider.

## 3. Décision d'archi A1 — à valider avant code

### Problème

`FederationMediaSourceProvider.BuildMediaSource` assigne `Id = $"jellyfed:{item.Id}:{source.PeerName}"`. Ce n'est pas un Guid. Quand un client demande à transcoder une source alternative (HEVC navigateur, etc.), le pipeline HLS Jellyfin fait `Guid.Parse(MediaSourceId)` → `System.FormatException: Guid should contain 32 digits` → crash. La source native (`.strm`) marche, les alternatives non dès qu'un transcodage est requis.

### Options analysées et écartées

1. **Workaround `SupportsTranscoding=false`** : 30 LOC, débloque dew (B1 = direct-play obligatoire), mais casse les autres clients JF (Android/iOS/web sans codec) qui se prennent une erreur « pas de source compatible ». Acceptable en v0 mais pas pour livrer une expérience complète.

2. **LiveStream pattern (`IMediaSourceProvider.OpenMediaSource`)** : la voie théoriquement propre, mais conçue pour les flux **live** (durée infinie, pas de seek garanti). Nos sources sont des fichiers (durée finie, seek nécessaire). Peu documenté, risque réel de ne pas fonctionner après 2-3 jours de dev. Refusé pour cette v1.

3. **Matérialiser un `.strm` par source sous sous-dossier `sources/`** : crée des items JF distincts (vrais Guid → transcode marche), puis appelle `MergeVersions` natif JF pour les fusionner en 1 item N sources. Mais layout disque dupliqué × N peers, sous-dossier `sources/` à introduire, contrat layout v1 cassé.

### Option retenue — Aplatissement du layout

Layout cible :

```
/jellyfed-library/Films/
└── Anora (2024) [tmdbid-1064213]/        ← 1 dossier par item (pas de sous-dossier par peer)
    ├── Anora (2024) [peer-B].strm
    ├── Anora (2024) [peer-B].nfo
    ├── Anora (2024) [peer-C].strm
    ├── Anora (2024) [peer-C].nfo
    ├── poster.jpg                          ← partagé (premier sync gagne)
    └── fanart.jpg                          ← partagé

/jellyfed-library/Series/
└── Breaking Bad (2008) [tmdbid-1396]/     ← 1 dossier série pour tous les peers
    ├── tvshow.nfo                          ← partagé
    ├── poster.jpg, fanart.jpg              ← partagés
    └── Season 01/
        ├── BB - S01E01 [peer-A].strm
        ├── BB - S01E01 [peer-A].nfo
        ├── BB - S01E01 [peer-C].strm
        └── BB - S01E01 [peer-C].nfo
```

Le nom du dossier reprend la convention `Title (Year) [tmdbid-XXX]` pour matcher la biblio locale (`/srv/media/Films/Anora (2024) [tmdbid-1064213]/`). Chaque `.strm` est un item JF distinct avec un vrai Guid. MergeVersions par TMDB fusionne tout (films + épisodes individuels).

### Conséquences directes

| Aspect | Avant (per-peer) | Après (aplati) |
|---|---|---|
| Sous-dossier par peer | `/Films/{peer}/{title}/` | `/Films/{title}/` |
| Skip TMDB local (ligne 286) | présent | **supprimé** (A4 résolu) |
| `FederationMediaSourceProvider` | actif, lit `sources.json` | **supprimé** (~250 LOC) |
| Sidecar `sources.json` | écrit à chaque sync | **supprimé** |
| `EpisodeSources[]` dans le manifest | utilisé | **supprimé** (le tracking se fait par `.strm` path) |
| Fusion multi-source | Provider custom au runtime | MergeVersions natif JF (post-sync) |
| Promotion peer primaire | déplacement de dossier | **plus nécessaire** (pas de peer primaire au niveau disque) |
| Pruning peer | `rm -rf {Root}/{peer}/` | suppression par nom de fichier (`*[peer-X].strm`) + cleanup dossiers vides |

### Implications opérationnelles

- **Bibliothèque JF côté user** : il faut configurer la bibliothèque « Films » pour scanner **2 racines** (`/srv/media/Films` + `/jellyfed-library/Films`). Idem pour « Séries ». À documenter dans `README.md` (section Installation) + page de config du plugin (UI hint).
- **Auto-merge JF des `.strm` multi-versions dans le même dossier** : à valider en test. Si JF auto-merge → on n'a même pas besoin d'appeler MergeVersions explicitement. Sinon, fallback : appel à `ILibraryManager` direct (réplique de la logique du controller `/Videos/MergeVersions`, cf. `MergeVersionsManager.cs` du plugin `danieladov/jellyfin-plugin-mergeversions` pour référence).
- **NFOs/images partagés (race au write)** : pour `poster.jpg`, `fanart.jpg`, `tvshow.nfo`, premier peer arrivé pose le fichier, suivants l'ignorent (test `File.Exists` avant écriture). Le contenu étant identique (mêmes métadonnées TMDB), peu importe qui gagne. NFOs par peer (`.strm.nfo`) restent distincts (un par fichier).
- **Conflit d'édition** : si peer B a `[edition-Director's Cut]` et peer C `[edition-Theatrical]`, le suffixe peer suffit (`Anora [edition-Director's Cut] [peer-B].strm` vs `Anora [edition-Theatrical] [peer-C].strm`). JF les voit comme 2 versions distinctes (probable) ; à valider en test, sinon contourner via MergeVersions manuel par TMDB.

### Plan d'implémentation A1 (proposition)

1. **`StrmWriter`** : renommer la logique pour écrire dans `{Root}/Films/{Title} ({Year}) [tmdbid-XXX]/{Title} ({Year}) [peer-PEER].strm` (pas de sous-dossier peer intermédiaire). Garder le tracking pour NFOs/images partagés (idempotence via `File.Exists`).
2. **`FederationSyncTask`** :
   - Supprimer le skip ligne 286 (`if (!string.IsNullOrEmpty(item.TmdbId) && localTmdbIds.Contains(item.TmdbId))`).
   - Adapter la structure `Manifest` : la clé reste `tmdb:XXX`, mais `ManifestEntry.Sources[]` devient le tracking par-`.strm` (chaque Source porte son `StrmPath`).
   - Après sync, appeler MergeVersions par TMDB (ou laisser JF auto-merger, à tester).
3. **`PruneEntriesAsync`** : adapter le cleanup. Pour chaque source pruned : supprimer son `.strm` + son `.nfo`. Si le dossier `/Films/{title}/` se retrouve vide (plus aucun `.strm`) → supprimer aussi `poster.jpg, fanart.jpg, tvshow.nfo` et le dossier.
4. **Supprimer `FederationMediaSourceProvider.cs`** + l'enregistrement dans `PluginServiceRegistrator.cs`. Supprimer `SourcesFile.cs` + écriture dans `StrmWriter`.
5. **Supprimer `SeriesEpisodeSourceGroup.cs`** + champs `EpisodeSources[]` dans `ManifestEntry`.
6. **Documenter le changement de layout** dans `docs/strm.md` + bump `schemaVersion` du manifest (1 → 2) + écrire la migration dans `SchemaMigrator` (option : si on n'a aucun user en prod, juste refus de démarrage avec message clair « reset network requis » comme prévu dans le contrat v1).
7. **Tests** : créer 1 cas de test e2e avec 3 instances + 1 film présent sur 2 peers + 1 série présente sur 2 peers + 1 film local + chez un peer (cas A4). Vérifier que JF affiche 1 carte par item avec N sources.
